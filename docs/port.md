# 移植与适配方案

> 目标不是"能跑"，是**完全符合平台契约**：单文件 ESM、平台循环、平台输入、平台存档、平台可调项（金手指 / 设置 / 成就）。
> 参考：`../../hearthbox/docs/game-sdk.md`、`porting.md`、`tuning.md`、`plugins.md`。

## 1. 现状与目标

| 项 | 现在（demo） | 目标 |
|---|---|---|
| 加载 | `index.html` + 7 个 `<script>`，挂 `window.TS` | `game.js` 单文件 ESM，默认导出 `defineGame()` |
| 主循环 | 自有 rAF + 累积器 | 平台驱动，`dt` 恒为 `1/60` |
| 输入 | `navigator.getGamepads()` + 键盘监听 | 只读 `ctx.input` |
| 存档 | `localStorage`（`util.js` 两处） | `ctx.storage` |
| 随机 | `Math.random()` 17 处 | `ctx.random` |
| UI | 80 处 DOM 操作，全在 `main.js` | 全部画在 `ctx.ctx2d` |
| 音频 | 自建 `AudioContext` | `ctx.audio.ctx` + `music`/`sfx` 总线 |
| 可调项 | 无 | 金手指 6 项 / 设置 4 项 / 成就 6 项 |

## 2. 目标结构

```
tank-survivors/
├── game.json              平台清单
├── package.json           @hearthbox/sdk: file:../hearthbox/packages/sdk
├── tsconfig.json
├── vite.config.ts         打包成单文件 game.js，SDK 内联
├── docs/                  设计文档（见下表）
├── src/
│   ├── main.ts            defineGame 入口 + 状态机 + 接线，只做编排
│   ├── config.ts          常量：分辨率、色板、技能表、敌人表、波次表
│   ├── tanks.ts           八台坦克：点数、武器、签名、涂装
│   ├── levels-table.ts    坦克等级曲线、签名 4 阶表、外观阶段
│   ├── stats.ts           底盘换算 + 等级缩放 + 流派加成合成，纯函数
│   ├── tuning.ts          可调量 + declareOptions() + resolveTuning()
│   ├── save.ts            存档读写、废铁结算、解锁
│   ├── world.ts           地形生成与碰撞（5 套生成器 + 通行判定）
│   ├── camera.ts          合屏 / 分屏状态机、跟随、钳制
│   ├── game.ts            实体与规则（update 侧）
│   ├── enemies.ts         敌人行为表 + 精英词缀
│   ├── fx.ts              特效总线与粒子池
│   ├── render.ts          全部绘制（render 侧），含双视口
│   ├── ui.ts              画布内菜单：标题 / 机库 / 暂停 / 升级 / 结算
│   ├── input.ts           把 ctx.input 归一成"动作"
```

## 3. 四步改造（每步都能跑）

### 第 1 步：能加载（半天）

1. 加 `game.json`、`package.json`、`tsconfig.json`、`vite.config.ts`
2. 新建 `src/main.ts`：`defineGame({ id, create })`，画一个背景色 + 一个方块证明链路通
3. `npx vite build` → `dist/game.js`
4. 平台 `pnpm dev`，货架上出现"坦克幸存者"，点进去能看见方块

**这一步不碰任何旧代码**，先用空壳证明"平台能加载我"。**旧代码留在仓库里当参考**，逐步搬。

### 第 2 步：玩法搬进来（1 天）

按依赖顺序搬，每搬完一块就能玩：

| 顺序 | 搬什么 | 从哪 |
|---|---|---|
| 1 | 地形生成与碰撞 | `world.js` → `src/world.ts`（`Math.random` → `ctx.random`），再扩成 5 套生成器 |
| 2 | 相机与分屏状态机 | 新写（`docs/camera.md`），demo 没有 |
| 3 | 玩家移动 + 瞄准 + 射击 + 冲刺 | `game.js` 第 400–660 行 |
| 4 | 坦克底盘与签名技能 | 新写（`docs/tanks.md`），demo 没有 |
| 5 | 敌人与刷怪 | `game.js` 第 975–1100 行 + 波次表；刷怪改按玩家分环，兵种扩到 11 种 |
| 6 | 碰撞与伤害 | `game.js` 命中判定段 |
| 7 | 特效总线 | 新写（`docs/fx.md`），把 demo 里散落的 `addParticles` 收进来 |
| 8 | 经验、升级、卡池 | `game.js` 第 1520–1630 行，卡池换成 5 流派 × 4 级 |
| 9 | BOSS | `game.js` 第 1021–1100 行 |
| 10 | 绘制 | `render.js` 全量，改成 960×540 坐标系 + 双视口 |

**搬的时候同步做三件事**，不要留到最后：
- 所有 `Math.random()` → `ctx.random`
- 所有裸数值 → `config.ts` / `baseline`
- 所有 `document.*` → 删掉，对应功能进 `ui.ts`

**新增的块是新写而不是搬**：分屏相机、坦克底盘、特效总线、5 套地形生成器、11 种敌人行为。demo 里只有零散的雏形（`cam` 对象、`calcStats`、`addParticles`、单一 `World.generate`、5 种敌人），当参考不当代码。

### 第 3 步：UI 搬进画布（1 天）

这是唯一的重写。按玩家看到频率排序：

| 优先级 | 界面 | 内容 | 状态 |
|---|---|---|---|
| 1 | HUD | 存活时间、等级、经验条、击毁、血条、炸弹、护盾；分屏时两套玩家卡 | 一直在 |
| 2 | 升级选卡 | 3 张卡、焦点框、流派色条、等级点 | 每次升级 |
| 3 | 结算 | 时间、击毁、得分、新纪录、**本局废铁**、重开 / 回机库 | 每局结束 |
| 4 | 机库 | 三个页签：坦克（8 台 + 涂装 + 等级强化）/ 地图（5 张）/ 威胁（4 级） | 每局开始 |
| 5 | 暂停 | 继续 / 返回机库 / 金手指提示 / 退出 | 随时 |
| 6 | 标题 | 单双人选择、总废铁、最佳战绩 | 首次进入 |

**进化预览**是机库里的第四个界面：按 `north` / `Y` 打开该车的完整进化线（4 档外观 + 4 阶签名）。它是唯一的多页界面，做好状态管理（从哪进、退到哪）。

**焦点状态是唯一的难点**：每个菜单维护 `focus` 索引，`up/down/left/right` 移动、`south` 确认、`east` 返回。**机库有两层**：页签切换（横向）+ 网格内移动（行列换算），要写清楚焦点在页签上还是网格里。平台不提供画布内焦点系统，自己写（约 120 行）。

### 第 4 步：平台能力接线（半天）

| 能力 | 接法 |
|---|---|
| 存档 | `ctx.storage.get('progress')` / `.set()`，BOSS 击杀与通关立刻写 |
| 金手指 | `tuning.ts` 里 `declareOptions(ctx)` + `resolveTuning(ctx)`，逻辑只读 `tuning` |
| 设置 | 同上，`scope: 'setting'`；震动、伤害数字、自动瞄准读 `tuning` |
| 成就 | `scope: 'status'`，进游戏时声明快照 |
| 音频 | 接 `ctx.audio.sfx`，暂停时由平台挂起 |
| 震动 | `ctx.rumble(strong, weak, ms)`，受击与爆炸时调用 |
| 退出 | 暂停菜单的"退出"调 `ctx.exit()` |

## 4. 已知的坑

| 坑 | 说明 | 对策 |
|---|---|---|
| 空格既是冲刺又是确认 | 平台把 `Space` 映射到 `south` | 由状态机分流：非菜单时 `south` = 冲刺，菜单时 = 确认。不要同时读 `keyboard.pressed('Space')` |
| 双人键位冲突 | 平台键盘层只有一套 `south` | 双人模式第二人主要靠第二只手柄；键盘玩家共用一套动作键（同屏协作，不冲突） |
| 双人分屏边界抖动 | 距离在阈值附近反复横跳会晕 | 滞回 + 1.2s 驻留 + 0.22s 转场，见 `docs/camera.md` |
| 分屏时绕中点刷怪 | 敌人离两人都远，出现空场 | 按玩家分别刷环，环半径随该玩家视口算 |
| 高倍缩放时特写糊 | `fit` 缩放 + 大量细线 | 颜色用整色不用渐变；模糊只靠透明度 |
| 签名技能互斥 | 8 台坦克 8 个签名，容易写成 8 段 if | `SIGNATURES` 表 + 钩子（`onUpdate` / `onFire` / `onHit`），逻辑不认具体坦克 |
| 地形判定散落各处 | 每加一张图就要改移动、AI、弹道、刷怪 | 统一 `canPass(tankId, tile)` + `hasLineOfSight()`，只在 `world.ts` 实现一次 |
| 不能渡水的坦克进了水网图 | 玩家选了图才发现过不去 | 机库地图页签直接显示"当前坦克：渡水 否"，不靠玩家记 |
| 草丛变成单向隐身 | 敌人看不见你、你看不见它才公平 | 双向遮挡 + 草叶摇动 + 可烧掉，三条一起，见 `docs/maps.md` 第 4 节 |
| 敌人压力失控 | demo 的 `1 + t/100` 到 8 分钟是 5.8 倍，再乘刷怪翻倍 = 60 倍 | 阶段表上限 4.0 + 压力预算比值 0.85–1.15，实测盯这个比值 |
| 坦克等级把平衡打乱 | 加永久属性会让压力预算失效 | 点数定形态、等级定尺度；同等级下八台车的强弱关系不变 |
| 等级与威胁互相抵消 | 都涨 1.6 倍等于没变，玩家觉得坐跑步机 | 威胁数值只差 70%，难度靠兵种数 5→10 与精英率；且高威胁给废铁倍率 |
| 新坦克 1 级像变弱 | 刚花 2600 买的车比满级旧车差 | Lv1→5 只要 280 废铁，打完一局就回来；升级提示明示"花 280 可开威胁 2" |
| 进化线变成 8 份重复劳动 | 8 台车各写 4 档外观 | 通用装饰按阶段参数化，只有王牌特征每车独立（8 组） |
| `ctx.input.players` 长度恒为 4 | 未连接的 `connected === false` | 开双人前检查 `players[1].connected`，否则退化为单人并提示 |
| 存档 `status` 值不会自动刷新 | 平台只在 `declare` 时取值 | 进游戏声明一次快照；不承诺会话内实时更新 |
| 面板手柄不可用（平台 M3 未做） | 金手指面板只能鼠标/键盘 | 游戏内**不依赖**平台面板；关键操作（选卡、暂停）自己画 |
| `Math.random` 复现不了 | 平台不改 `Math.random` | 全部换 `ctx.random`，`?seed=42` 可复现整局 |
| 电视上 12px 中文字糊 | 系统字体渲染 | 正文最小 12px，重要信息用图形+短标签 |
| 首帧 `ctx2d` 状态残留 | 平台可能在上一局改过 `lineWidth`、`font` | `render()` 开头统一重置：`textAlign`、`lineWidth`、`globalAlpha`、`imageSmoothingEnabled` |

## 5. 提交粒度

每步一个提交，可回滚、可单独验收：

```
feat: 平台清单与构建配置，货架能识别
feat: 地形、相机与合屏/分屏状态机
feat: 玩家移动、射击、冲刺、坦克底盘
feat: 敌人、波次、伤害、按玩家刷怪
feat: 特效总线与 8 台坦克签名特效
feat: 技能体系（5 流派 × 4 级 + 终极）与三选一
feat: BOSS 与结算
feat: 画布内 UI（HUD / 机库 / 暂停 / 升级 / 结算 / 标题）
feat: 废铁结算、解锁与涂装
feat: 平台可调项接线（金手指 / 设置 / 成就）
test: 金手指生效与存档往返
docs: 验收截图
```
