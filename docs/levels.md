# 关卡与节奏

> 单局 8 分钟。地图在机库里选（见 `docs/maps.md`），但**时间轴上的关卡是固定的**：每一段都是固定的兵种配方与压力形态。
> 所有时间点写死在这里，代码里只引用常量，不改数值。

## 1. 结构

```
0:00        1:30        3:00        4:30        6:00        7:00        8:00
 |── 集结 ──|── 推进 ──|── 压制 ──|── 割据 ──|──── 终局 ────|
                              ▲ BOSS 1                ▲ BOSS 2（击杀即胜）
```

| 阶段 | 时间 | 刷怪（只/秒） | 兵种池 | 玩家该学到什么 |
|---|---|---|---|---|
| 一 · 集结 | 0:00–1:30 | 1.1 → 1.6 | 轻型、侦察 | 边退边打；砖墙能被自己的炮弹打穿 |
| 二 · 推进 | 1:30–3:00 | 1.6 → 2.4 | +炮手 | 别站在开阔地；优先点掉炮手 |
| 三 · 压制 | 3:00–4:30 | 2.4 → 3.2 | +迫击、+自爆 | 冲刺的时机；用掩体挡爆炸 |
| 四 · 割据 | 4:30–6:00 | 3.2 → 3.8 | +重装、+狙击（威胁 3+） | 绕位；开始有支援兵种 |
| 五 · 终局 | 6:00–8:00 | 3.8 → 4.0（封顶） | +召唤、+护卫（威胁 3+） | 收尾，把攒的流派打出去 |

**刷怪速率大幅下调**（原设计 1.1 → 10，现为 1.1 → 4.0）。原因见 `docs/enemies.md` 第 7 节的压力预算：原曲线配合血量倍率会把压力推到 60 倍，必然变成"一堵墙"。**密度靠上限和兵种质量控制，不靠每秒刷多少。**

**同屏上限**：60 / 90 / 115 / 140 / 155（按阶段递增，见 `docs/enemies.md` 第 7 节）。

**具体兵种池随威胁等级变化**——同一张时间轴，威胁 1 只有 5 种兵，威胁 4 有 10 种。完整表见 `docs/enemies.md` 第 4 节。

## 2. 波次节点

**节点是"有形状的一波"，不是随机撒怪。** 每个节点按固定阵型投放，让玩家能识别"这是哪一波"。

| 时间 | 节点 | 数量与阵型 | 意图 |
|---|---|---|---|
| 0:00 | 开场包围 | 轻型坦克 ×6，半径 560 环形 | 立刻有事做，不给空场 |
| 0:30 | 装甲纵队 | 轻型坦克 ×10，单侧纵向推进 | 教玩家"用通道卡位" |
| 1:00 | 侧翼夹击 | 侦察车 ×6，左右各 3 | 教玩家别只盯正面 |
| 1:30 | 炮手分队 | 炮手 ×4 + 轻型 ×8 | 第一次被远程打到 |
| 2:00 | 火力压制 | 炮手 ×6，固守砖墙后 | 逼玩家拆掩体进攻 |
| 2:30 | 精英推进 | 精英重装 ×1 + 轻型 ×10 | 第一次遇到"打不动" |
| 3:00 | 混合编队 | 轻型 ×8 + 侦察 ×8 + 炮手 ×4 | 三种威胁同时出现 |
| 3:30 | 自爆冲锋 | 自爆车 ×6，正面直线 | 教玩家用冲刺躲爆炸 |
| 4:00 | **BOSS · 铁壁** | 重装坦克 BOSS ×1（+ 4:20 召唤护卫 ×6） | 第一个阶段检查点 |
| 4:30 | 焦土 | 全类型随机 ×18，精英率 ×2 | BOSS 后立刻加压 |
| 5:00 | 双线突击 | 两侧各 8 只，同时 | 逼玩家分身 |
| 5:30 | 围剿 | 环形包围 ×16 + 自爆车 ×4 | 最密集的一波 |
| 6:00 | 最后抵抗 | 全类型 ×24，精英率 ×3 | 终局前的门槛 |
| 6:30 | 静默 | 刷怪速率 ×0.35，持续 25 秒 | 喘息、捡经验、补炸弹 |
| 7:00 | **BOSS · 终焉要塞** | 终焉要塞 MK-II ×1，常规刷怪停止 | 击杀即胜 |

节点之间的空档由基础刷怪速率填充。**节点不替代基础刷怪，而是叠加**——所以 2:30 那波的精英重装是"额外的"，不是"本该有的"。

**节点按威胁等级替换兵种，不按地图替换。** 例如"炮手分队"在威胁 1 是炮手 ×4，在威胁 3 换成狙击手 ×3 + 炮手 ×4。地图只改变**投放位置**（水网会优先从河道包抄），不改变节点本身。

## 2.5 地形介入的节点

五张地图各有一个**专属节点**，插在固定时间点，用来展示这张图的地形。这不增加关卡数，只是把同一段时间的投放换一种形态。

| 地图 | 时间 | 节点 | 内容 |
|---|---|---|---|
| 试验场 | — | 无 | 基准图不加专属节点 |
| 丛林 | 2:15 | 草中伏击 | 8 只轻型从草丛中出现（它们在草里时不可见） |
| 丛林 | 5:15 | 焦土推进 | 12 只敌人沿直线推进，路上草丛全被点燃 |
| 冰原 | 3:20 | 冰面冲锋 | 10 只侦察车从冰面高速滑入，速度比平时快 40% |
| 水网 | 2:40 | 渡河包抄 | 6 只侦察 + 4 只自爆从深水直接过河（只能过水的兵种） |
| 水网 | 5:40 | 断桥 | 桥被"敌人"打塌（其实是脚本），逼玩家走浅滩 |
| 废墟 | 3:10 | 塌楼 | 3 栋残楼同时进入预警，0.6s 后倒塌（不分敌我） |

**每个专属节点只出现一次**，且都有预警（草丛摇动、冰面划痕、水波纹、楼体抖动）。**它们都不改变基础刷怪**，是叠加的"事件"。

## 3. BOSS

### 铁壁（4:00）

| 项 | 值 |
|---|---|
| 血量 | 2800 |
| 半径 | 36 |
| 移动速度 | 38 |
| 行为 | 缓慢逼近；每 2.3s 三连扇形炮击；血量 50% 以下频率 ×1.35 |
| 召唤 | 血量 66% 与 33% 各召唤护卫 ×6 |
| 掉落 | 炸弹 +1、大面积经验球 ×12 |

### 终焉要塞 MK-II（7:00）

| 项 | 值 |
|---|---|
| 血量 | 8200 |
| 半径 | 46 |
| 移动速度 | 30 |
| 阶段一（100%–55%） | 环形弹幕每 3.2s 一圈 16 发；缓慢转向 |
| 阶段二（55%–0%） | 环形弹幕 + 定向扇形 + 召唤自爆车 ×4 每 8s；移速 +25% |
| 击杀 | 立即胜利，结算画面 |

**两个 BOSS 都不做无敌帧、不做阶段转场动画。** 玩家要的是"打得更狠"，不是"看得更多"。

## 4. 地形（每张地图不同）

**地形规则不在这份文档里**——五张地图的完整设计（草丛、冰面、深水、废墟）见 `docs/maps.md`。

这里只保留所有地图共用的结构：

| 元素 | 规则 |
|---|---|
| 外墙 | 一圈钢，不可摧毁 |
| 出生空地 | 半径 205，永远留空，保证开局不憋屈 |
| 出生外环掩体 | 12 处（22% 跳过），提供第一层掩体 |
| 地图尺寸 | 2000–2400 × 1600–1800，按地图不同 |

**关键设计**：可破坏的地形（砖墙、草木、残楼、桥）**不重生**。一局打到 6 分钟时，战场会从"迷宫"变成"开阔地"——这是主动的节奏变化，也是玩家自己的破坏造成的。所以**越到后期越没有掩体**，压力天然上升，不需要额外加数值。

## 5. 补给节奏

| 时间 | 补给 | 位置 |
|---|---|---|
| 1:30 / 3:00 / 4:30 / 6:00 | 维修箱（回 30 HP）＋ 炸弹 +1 | 地图随机空地，靠近当前玩家 |
| BOSS 死亡 | 炸弹 +1、经验球 ×12 | BOSS 位置 |
| 每次升级 | 三选一卡 | 暂停整个世界 |

补给只在节点时间点刷，不随机掉落——**玩家能预期它**，才不会被迫赌运气。

**水网例外**：补给不刷在深水里（否则不能渡水的坦克永远拿不到）。刷在水边最近的空地上。

## 6. 双人规则

| 项 | 值 |
|---|---|
| 同屏 | 是，共享一台电视；**动态分屏**，靠近合屏、拉开分屏（规则见 `docs/camera.md`） |
| 倒下 | 一人血量归零 → 倒地，2.2 秒救援计时开始 |
| 救援 | 队友贴近 48px 内，持续 2.2 秒救起（进度环可见） |
| 全灭 | 两人同时倒地 → 失败 |
| 经验 | 共享等级，两人同时选卡（一张卡对全队生效） |
| 镜头 | 合屏跟两人中点，分屏各自跟随；一人倒地时强制合屏 |

## 7. 结算

| 字段 | 来源 |
|---|---|
| 存活时间 | `game.time` |
| 击毁数 | `game.kills` |
| 获胜 | 击杀终焉要塞 |
| 得分 | `存活秒 × 4 + 等级 × 110 + 击毁 × 12 + 通关 5000` |
| 废铁 | `击毁 × 0.4 + 存活秒 × 0.5 + BOSS × 120 + 通关 400`（失败也给） |
| 新纪录 | 与 `ctx.storage` 里的最佳战绩比较 |
| 用过金手指 | 存档里记 `cheated: true`，结算页标一个小标记 |

废铁在**结算时立刻写进存档**，不等玩家点"返回"——Android 可能直接杀进程。
