## 帧预算

60Hz 下每帧 16.6ms。平台自身开销 ≤ 1ms（`docs/compatibility.md`），给游戏留 15ms。

| 项 | 预算 | 实测目标 |
|---|---|---|
| 逻辑更新 | ≤ 5 ms | 同屏 165 敌 + 200 弹 |
| 绘制 | ≤ 8 ms | 单次 `fillRect` / `arc` 为主，无 `drawImage` |
| 实体上限 | 敌 200 / 弹 400 / 粒 900 / 飘字 90 / 火池 40 | 超出即丢弃新增 |
| 内存 | 无每帧分配 | 复用数组与临时向量，`splice` 只在移除时 |

## 存档

| 键 | 内容 | 上限 |
|---|---|---|
| `progress` | 最佳战绩（时间/分数/等级/击毁/通关次数/金手指标记）、已解锁坦克、已购涂装、废铁余额、当前选用坦克 | 单条 < 2KB |
| `stats` | 累计统计（总击杀、总时长、BOSS 击杀数、每台坦克的场次与胜场） | 单条 < 2KB |

**关键进度立刻 `set`**：废铁结算、坦克解锁、新纪录、通关，不攒到退出——Android 可能直接杀进程。平台单游戏上限 1MB，这个用量远远够。

> `status` 项是只读的：平台面板只显示值，不提供控件。
>
> **已知限制**：平台的 `OptionsApi` 只有 `declare`，没有"更新已有项的值"的方法，而且重复 `declare` 同一个 id 会抛错（`option-store.ts` 第 147 行）。所以实现上只能是"进入游戏时声明一次快照"，本次会话内不会刷新。
>
> 这意味着成就面板显示的是**上一次退出时**的纪录。要改成实时值，需要平台给 `OptionsApi` 加一个 `setStatus(id, value)`——那是平台改动，不在本仓库范围内。当前做法是能力边界内的正确选择，已记录在 `docs/port.md` 的"已知的坑"。
