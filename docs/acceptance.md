# 验收清单

> `typecheck` 通过不算跑通。改到玩家可见的东西，必须真跑起来并截图。

## 每次改动后的最小检查

```bash
cd ../hearthbox
pnpm dev
```

- [ ] 游戏出现在货架上，名字和简介正确
- [ ] 点进去不是黑屏，没有崩溃页
- [ ] 控制台没有红色报错

- [ ] `dist/game.js` 里没有裸导入（搜 `from '@hearthbox/sdk'` 必须为 0 处）

- [ ] 全文没有 `document.`、`querySelector`、`innerHTML`
- [ ] `Math.random` 为 0 处（全部走 `ctx.random`）
- [ ] `game.json` 的 `id` 与 `defineGame({ id })` 一致

### 能玩

- [ ] 键盘能完成一局（WASD / 方向键 + 空格 + Shift）
- [ ] 手柄能完成一局（如果有手柄）
- [ ] 死亡后能重开，不用刷新页面
- [ ] 有明确的开始和结束
- [ ] 8 分钟能打到终焉要塞，击杀后进入胜利结算

### 敌人

- [ ] 11 种敌人都能实际出现（用威胁 4 + 打满 8 分钟验证）
- [ ] 每种敌人的预警都可见（炮口闪光、狙击红线、迫击收缩圈、自爆闪红）
- [ ] 屏幕外没有狙击手蓄力（只在 620px 且有视线时）
- [ ] 重装坦克正面减伤 60% 生效，绕后就打穿
- [ ] 精英词的 5 种词缀都能出现，视觉可辨
- [ ] 单次受击不超过最大生命 30%（除自爆 / BOSS 蓄力 40%）
- [ ] 压力比值：打满 8 分钟，场上敌人数缓慢上升后稳定，不是瞬间堆满

### 地图与地形

## 踩坑记录

遇到问题时记在这里，下次不重复踩：

| 现象 | 原因 | 解法 |
|---|---|---|
| 进游戏直接崩溃页：`可调项 xxx：choices 至少两项` | 平台 `validate()` 要求 `choice` 至少两项，我把成就项写成单项 | 成就不要做成可调项；改用画布内界面 |
| 机库只画出 3 台坦克，第 4 列与第二行全黑 | `drawTank` 里 `g.restore;` 漏了括号 → 画盾牌侧板时泄漏 save 状态，污染后续所有绘制 | 补上 `()`；这类 bug 用像素探针定位最快 |
| 双人局一人倒地后永久卡死 | `updatePlayer` 对 `!alive` 直接 return，`reviveT` 永不倒数；`tryRevive` 从未被调用 | 新增 `updateDowned` 并接进 update 循环 |
| 成就面板数字永远不变 | 平台可调项"已保存值优先于 declare 默认值"，且没有 `setStatus` | 不在平台声明，改在机库里实时读存档 |
| **敌人站着不动** | `seek(e, dt, ux, uy, 0)` —— 不带攻击的敌人（轻型/侦察/重装）throttle 传了 0，速度恒为 0 | 传 1。凡是"参数是倍率"的地方，0 都是危险的默认值 |
| **金手指勾了没反应** | `declare` 了 6 条，但 `tuning.moveSpeed` / `fireInterval` 从未被任何代码调用 —— 面板能拖，游戏不读 | 每个可调量都要有真实调用点；写完 grep 一遍 `tuning.xxx` 的使用次数 |
| 经验倍率实际是平方 | 拾取时乘了一次，`tuning.xpNeed` 里又除了一次 | 倍率只在一个调用链上生效 |
