# 技能体系（设计意图）

> **本文只讲"为什么这样设计"。具体卡片、数值与卡池规则见 `docs/cards.md`。**
> 两份文档冲突时，以 `cards.md` 为准（它包含最新修正的数字）。

## 1. 为什么是"5 流派 × 4 级 + 终极"

三个选择都被排除过：

| 方案 | 问题 |
|---|---|
| 无限叠（每次升级都给同一批卡） | 后期抽到"再升一次主炮"这种无效选项，每次升级不再有意义 |
| 只有数值，没有形态 | 玩家感觉不到变化，只是数字在涨 |
| 40 张以上的大池 | 一局只拿 12 张，摸不到的都是装饰 |

**当前方案的核心**：4 级封顶 → 每张卡都有明确的终点 → 每次升级都必须有意义。终极卡是"质变"，不是"更大的数值"。

## 2. 每流派 4 级的节奏

```
Ⅰ 入门数值  →  Ⅱ 形态变化  →  Ⅲ 进阶数值  →  Ⅳ 形态强化  →  终极质变
```

**Ⅱ 级必须是形态卡**（并联 / 穿透 / 爆炸 / 布雷 / 护盾），不能是数值。这是"玩家能不能感觉到变化"的分界线：

| 流派 | Ⅱ 级的形态变化 |
|---|---|
| 火力 | 并联多一发 |
| 穿透 | 硬化弹体（能打地形） |
| 爆破 | 破片衬层（范围扩大） |
| 自动化 | 布雷器（新增召唤物） |
| 生存 | 强化引擎（机动性） |

## 3. 为什么一局只拿 12 张

这是整套设计的支点，也是我最初设计错的地方。

**错误版本**：曲线太松，一局通关能拿 17–19 张，覆盖卡池 68–76% —— 那不是选择，是清单。

**当前**：12 张覆盖 48%，**5 条流派里必须放弃 3 条**。每次升级都在做减法，这才叫构筑。

推导与实测数据见 `docs/cards.md` 第 1 节。

## 4. 三条硬规则

| 规则 | 内容 | 为什么 |
|---|---|---|
| **只改速率与形态，不改结构** | 经验倍率可以，直接改等级不行 | 关掉金手指后进度会错位（平台 `tuning.md` 硬规则 3） |
| **不改进度门槛** | 不能"这张卡让升级更快" | 会让"练级"变成唯一解 |
| **不做"必须某流派才能过"** | 任何流派组合都能通关 | 卡死 build 是最糟的挫败 |

## 5. 与平台可调项的分工

流派等级是**游戏内进度**，不进平台面板。平台面板只放"玩家在游戏外就能决定"的东西：

| 面板 | 项 | 为什么在这里 |
|---|---|---|
| 金手指 `cheat` | 移动速度、射速倍率、经验倍率、出怪速度、无敌、无限炸弹 | 玩家想怎么玩这个游戏 |
| 设置 `setting` | 屏幕震动、伤害数字、自动瞄准、瞄准辅助、双人分屏 | 体验偏好 |
| 成就 `status` | 最高存活、最高击毁、最高等级、通关次数、累计击毁、坦克收集度 | 只读展示 |

**把技能等级做成可调项等于让玩家买通关**，所以不做。

## 6. 数值放哪

| 内容 | 位置 |
|---|---|
| 卡池定义、每级效果、数值 | `src/config.ts` 的 `CARDS` 表 |
| 卡池抽取权重、保底 | `src/tuning.ts` 的 `baseline.offerQuality` |
| 计算后的属性 | `src/stats.ts` 的 `calcStats()`，只读表不写数字 |

**代码里不出现裸数值**：`calcStats()` 里不能写 `+5`、`×1.09`。

## 7. 与坦克签名、坦克等级的关系

| 系统 | 是否进卡池 | 是否会随等级变强 |
|---|---|---|
| 流派卡（本文档） | 是，唯一的卡池 | 不进 |
| 坦克签名 | 否，固有属性 | 随坦克等级 4 阶进化（`docs/tank-levels.md`） |
| 坦克底盘 10 点 | 否，选车时确定 | 不受等级影响（只放大尺度） |

**三条线互不重叠**：卡池管"这一局怎么长"，签名管"这台车是什么"，底盘管"它的基本形状"。

## 8. 重玩价值从哪来

不是靠随机卡池本身，而是靠 **12 张卡的分配压力 × 5 流派 × 8 坦克 × 5 地图 × 4 威胁**：

```
每次开局要做的决策：
  选哪台车（8）→ 选哪张图（5）→ 选哪个威胁（4）→ 12 张卡怎么分配（组合数远大于 1000）
```

**但复杂度不在卡池里**——卡池只有 25 张，玩家看完一遍就懂。复杂度在"选什么、放弃什么"。
