# 相机与分屏

> 这一份解决一个问题：**地图比屏幕大得多，双人什么时候合屏、什么时候分屏。**
>
> 核心判断：**地图尺寸应该由相机决定，不是反过来。** 先定相机能看清多少，再决定场地多大。否则一定会做出"永远在分屏"的地图。

## 1. 先算清数

| 项 | 值 |
|---|---|
| 逻辑分辨率 | 960 × 540 |
| 格尺寸 | 40 × 40 |
| 坦克直径 | 28（半径 14） |

**合屏时能看到多少世界**（缩放 = 世界像素 → 屏幕像素的倍率，越小看得越远）：

| 缩放 | 可见世界 | 占 960 屏宽 | 坦克在屏上的直径 |
|---|---|---|---|
| 1.04（最近） | 923 × 519 | 96% | 29 px |
| 0.90 | 1067 × 600 | 111% | 25 px |
| 0.66（最远） | 1455 × 818 | 152% | 18 px |

**分屏时**（左右各 480 × 540）：

| 缩放 | 可见世界 | 坦克在屏上的直径 |
|---|---|---|
| 0.90 | 533 × 600 | 25 px |

**结论**：坦克在屏上直径 18 px 是**可读性下限**（1080p 上 36 物理像素，3 米外仍可见）。所以合屏最小缩放定在 **0.66**，不再往下。

## 2. 三个方案，为什么选第三个

### 方案 A：始终合屏，靠缩放容纳两人

缩放一路降到两人都在画面里。问题是**两人相距越远，画面越糊越小**。地图上对角 2700 px，要装进 960 宽的屏，缩放得降到 0.35——坦克只剩 10 px，没法玩。

**否决**：缩放有物理下限。

### 方案 B：始终分屏

两人永远各占一半。问题是**一局里 70% 的时间两人都在一起**，分屏那一半画面全是浪费，而且视野被砍半，反而看不清全局。

**否决**：代价恒定，收益偶尔。

### 方案 C：动态分屏 + 滞回

近了合、远了分。唯一的难点是**边界抖动**——在阈值附近反复横跳会让人晕。

**采用**。用滞回（进入和退出用不同阈值）+ 驻留时间解决。

## 3. 判定：用"能不能装下"而不是"离多远"

不直接用距离，因为横向和纵向的屏幕比例不同（960 宽、540 高）。用**所需缩放**：

```
needW = |p2.x - p1.x| + 2 × 留白     // 留白 140 px
needH = |p2.y - p1.y| + 2 × 留白
fitZoom = min(960 / needW, 540 / needH)
```

`fitZoom` 的意思是：**要装下两人，最多能放大到多少**。它比下限还小，就说明合屏装不下了。

| 状态 | 条件 |
|---|---|
| 合屏 → 分屏 | `fitZoom < 0.66` |
| 分屏 → 合屏 | `fitZoom > 0.76` |

换成实际距离（留白 140）：

| 分离方向 | 触发分屏 | 触发合屏 | 滞回带 |
|---|---|---|---|
| 横向 | > 1175 px | < 983 px | 192 px |
| 纵向 | > 538 px | < 431 px | 107 px |

**纵向先分屏**，因为 540 的高度装不下多少人。这不是 bug，是屏幕比例决定的。

再叠一层保护：**状态切换后驻留 1.2 秒**，期间不再切换。两个条件同时满足才动。

## 4. 状态机

```
                    fitZoom < 0.66 且驻留 > 1.2s
      ┌──────────┐ ──────────────────────────────► ┌────────────┐
      │  合屏    │                                 │   分屏中   │
      │ Merged   │ ◄────────────────────────────── │ Splitting  │
      └──────────┘     fitZoom > 0.76 且驻留       └────────────┘
            ▲                                              │ t ≥ 1
            │                                              ▼
      ┌──────────┐                                 ┌────────────┐
      │ 合屏中   │ ◄────────────────────────────── │   分屏     │
      │ Merging  │                                 │   Split    │
      └──────────┘                                 └────────────┘
```

| 转换 | 动画时长 | 说明 |
|---|---|---|
| 合 → 分 | 0.22 s | 分隔线从右边缘扫到中线 |
| 分 → 合 | 0.18 s | 反向收回 |

**转场不黑屏、不切镜**。两路相机在转场开始时都停在"合屏的中点相机"，随后各自 lerp 到自己的玩家身上。玩家看到的是画面被一条线推开，而不是视角突然跳走。

## 5. 转场怎么画

设 `t ∈ [0,1]` 为分屏进度：

```
dividerX = 960 - 480 × t
视口 A = [0,        0, dividerX,        540]   // P1
视口 B = [dividerX, 0, 960 - dividerX,  540]   // P2
```

`t = 0` 时 B 宽度为 0（等于合屏）；`t = 1` 时各 480。

- 视口 A 的相机位置 = `lerp(中点相机, P1 相机, t)`
- 视口 B 的相机位置 = `lerp(中点相机, P2 相机, t)`
- 两者的缩放都从 `合屏缩放` lerp 到 `0.90`

两块各自 `save → clip → setTransform → 绘制 → restore`。**HUD 最后画，不裁剪**，跨在两块之上。

## 6. 相机跟随

| 模式 | 跟随目标 | 缩放 |
|---|---|---|
| 合屏 | 两人中点 + 瞄准前瞻 | `clamp(fitZoom, 0.66, 1.04)` |
| 分屏 | 各自玩家 + 瞄准前瞻 | 0.90 |

**前瞻**：目标点向玩家瞄准方向偏移 `40 × aimT`，让炮口前方多一点视野。`aimT` 在 0.5 秒内从 0 升到 1，松手后缓回 0，避免抖动。

**平滑**：`cam += (target - cam) × (1 - exp(-8 × dt))`。固定步长下等价于每帧插值 12.5%，不做逐像素死跟。

**边界钳制**：相机中心限制在 `[半宽, 地图宽 - 半宽]`。地图比视口还小时直接居中。分屏时两路各自钳制——这会导致靠近地图边缘的玩家偏在视口一侧，是正常的，不要为了"永远居中"而露出地图外的黑边。

## 7. 刷怪必须跟着相机走

这是分屏带来**必须改**的一条规则：**按玩家分别刷怪**。

```
每个存活玩家的刷怪速率 = 总速率 / 存活人数
刷新环半径 = max(该玩家视口半宽, 该玩家视口半高) + 80
角度随机，落在空地
```

| 模式 | 环半径 |
|---|---|
| 合屏（zoom 1.04） | 541 px |
| 合屏（zoom 0.66） | 808 px |
| 分屏（zoom 0.90） | 380 px |

**为什么不能绕着两人中点刷**：分屏时两人隔着 1500 px，绕着中点刷的敌人离谁都远，玩家会看到"空场"，然后一走开就被贴脸。按玩家刷，谁都不会闲。

双人总速率 ×1.35（不是 ×2），所以每人分到 0.675——比单人略轻松，但少了队友分担。**这就是"别走太远"的自然激励，不需要额外的惩罚规则。**

## 8. 强制合屏（不受阈值控制）

| 情况 | 原因 |
|---|---|
| 升级选卡 | 世界暂停，所有注意力在卡上 |
| 暂停菜单 | 同上 |
| 结算 / 标题 / 机库 | 全屏界面 |
| 单人模式 | 没有第二个人 |
| 一人倒地 | 见下 |

**一人倒地时强制合屏**，相机跟随仍站着的玩家，倒地者的位置用**屏幕边缘箭头**标示（带距离读数）。理由：倒地的人没事可做，分成两屏只会让他盯着一块没人动的画面。合屏能让他看清队友在哪、离救援还有多远。

被救起后 **0.6 秒**再重新判定是否需要分屏，避免刚起来就分。

## 9. 屏幕外指示

合屏时理论上两人都在画面内，但有两种情况会短暂出界：

- 分屏转场动画期间（`t` 还没到 1）
- 一人冲刺的瞬间超出了视口

兜底：视口外 60 px 以内不提示，超出则在该方向画一个**玩家色三角**贴在视口边缘，透明度随距离衰减（200 px 外完全实心）。

## 10. HUD 在两种模式下的布局

```
【合屏】
┌────────────────────────────────────────────┐
│          00:00    LV 3  ▮▮▮▯▯              │
│  HP ▮▮▮▮▮▯  炸弹 ●●●                        │
│                                            │
│              [ 战场 ]                      │
│                         P2 HP ▮▮▮▮▯ 炸弹 ●● │
└────────────────────────────────────────────┘

【分屏】
┌─────────────────────┬──────────────────────┐
│      00:00  LV 3 ▮▮▮▯▯  ← 跨屏顶栏          │
│ HP ▮▮▮▮▯            │ HP ▮▮▮▯▯             │
│ 炸弹 ●●●   P1        │ P2  炸弹 ●●          │
│                     │                      │
│      [ P1 视野 ]     │     [ P2 视野 ]       │
└─────────────────────┴──────────────────────┘
```

| 元素 | 合屏 | 分屏 |
|---|---|---|
| 计时 / 等级 / 经验 | 顶部居中，全屏一份 | 跨屏顶栏，全屏一份 |
| 血条 / 炸弹 / 冲刺 | 各自位置的角落 | 各自视口右下角 |
| BOSS 血条 | 顶部，全宽 | 顶部，全宽（压在顶栏下） |
| 伤害飘字 | 世界坐标 | 世界坐标，各自视口内 |

**跨屏顶栏**：横跨两个视口画一条半透明底衬，不裁剪。这样不管分不分屏，计时都在同一个位置。

## 11. 分屏的代价

| 项 | 合屏 | 分屏 | 对策 |
|---|---|---|---|
| 绘制调用 | 1 次全屏 | 2 次半屏 | 总量接近，只多一次变换设置 |
| 视锥裁剪 | 1 个矩形 | 2 个矩形 | 每个视口独立裁，总可见实体反而更少 |
| 每玩家可见面积 | 923 × 519 | 533 × 600 | 分屏后纵向反而看得更多 |
| HUD 绘制 | 1 遍 | 2 遍玩家卡 + 1 遍顶栏 | 可忽略 |

**分屏不会掉帧**，因为总像素量不变（960×540 被切成两块），只是多了一次 `clip` 和 `setTransform`。

## 12. 可调项

分屏是**玩家体验差异极大**的机制：有人喜欢，有人一看到就晕。所以给出选项。

`ctx.options.declare({ scope: 'setting' })`：

| id | 名字 | 类型 | 选项 | 默认 |
|---|---|---|---|---|
| `split-mode` | 双人分屏 | choice | `auto` 自动 / `never` 始终合屏 / `always` 始终分屏 | `auto` |

- `never`：缩放下限放宽到 0.52（两人永远同屏，但会很小），超出范围时用边缘箭头指示。
- `always`：始终分屏，无视距离。单人模式下忽略此项。
- `auto`：第 3 节的规则。

## 13. 为什么定 2200 × 1600

地图尺寸是被相机推出来的，不是拍脑袋：

| 候选 | 合屏可见占比 | 分屏频率 | 判断 |
|---|---|---|---|
| 2600 × 2000 | 61% | 频繁，几乎一直在分屏 | 太大，双人变成两个单人 |
| **2200 × 1600** | **65%** | **偶尔，两人分开时才分** | **采用** |
| 1600 × 1200 | 86% | 几乎不触发 | 太小，拆墙的空间不够 |

2200 × 1600（55 × 40 格）的取舍：

- 合屏最小缩放 0.66 时可见 1455 × 818，**占地图宽 66%**——两人稍微分开还在同一屏里
- 分屏触发距离 1175 px（横向），**占地图宽 53%**——要在场地两端才分屏
- 对角 2718 px，砖墙 62 处，足够"打穿一堵墙换一条路"的空间感

**一句话：地图大到能容纳拆墙战术，小到两人不该走散。**

## 14. 调试与验收

调试参数（`ctx.debug.enabled` 时生效，`?debug=1`）：

| 键 | 作用 |
|---|---|
| `F1` | 显示合屏判定值（`fitZoom`、`needW`、`needH`、当前状态） |
| `F2` | 强制分屏 / 强制合屏循环，测转场 |
| `F3` | 把两人瞬移到最大分离距离，测边界钳制 |

验收清单：

- [ ] 单人开局，全程合屏，画面不抖
- [ ] 双人贴近 5 分钟，从不分屏
- [ ] 双人拉开到 1300 px，0.22 s 内完成分屏，无黑屏
- [ ] 分屏后靠近到 900 px，0.18 s 内合屏
- [ ] 在阈值附近来回走 10 秒，状态切换不超过 2 次（滞回生效）
- [ ] 一人倒地，立刻合屏，边缘箭头指向倒地方向
- [ ] 在四种地图角落合屏/分屏，都不露出地图外黑边
- [ ] 打开设置改成"始终合屏"，双人拉到最远仍同屏 + 箭头指示
- [ ] 打开设置改成"始终分屏"，单人模式仍是合屏
