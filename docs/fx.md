# 特效总线

> 特效是这类游戏最值钱的部分，所以它不能散落在各处临时"加个爆炸"。
> **规则：所有特效都通过同一个总线触发，每种特效有确定的参数与上限。**

## 1. 为什么要有总线

如果每次命中都直接 `particles.push(...)`，会得到三个必然结果：

- 同一个视觉在不同代码路径下参数不一致（这里的爆炸大，那里的小）
- 无法统一关闭（可访问性要求）
- 无法统一限流（大量敌人同时死亡时帧率崩）

所以：**逻辑层只喊"发生了什么"，渲染层决定"画成什么样"**。

```ts
// 逻辑层（game.ts）
fx.emit('hit', x, y, { damage, crit, element });
fx.emit('blast', x, y, { radius, element });
fx.emit('kill', x, y, { size, element });

// 渲染层（fx.ts）唯一实现
```

## 2. 科技风格的三条视觉原则

这是"贴合未来科技"的具体做法，不是形容词。

| 原则 | 做法 | 反例 |
|---|---|---|
| **能量而非火药** | 爆炸用同心圆环 + 向外的细射线，不用烟团 | 一团褐色烟雾 = 二战 |
| **数据感** | 高速物体带一条**离散**拖尾（分段矩形，不是渐变） | 平滑渐变 = 普通光效 |
| **结构光** | 护盾、电磁用六边形网格或折线，不用纯色半透明圆 | 纯色圆 = 魔法护盾 |

具体到配色（色板见 `docs/art.md` 第 21 色）：

| 元素 | 主色 | 辅助 |
|---|---|---|
| 玩家炮弹 | `#ffe6b0` | 拖尾 `#f2b13c` |
| 穿透弹 | `#c9f5fb` | 拖尾 `#58c8d8` |
| 爆破 | `#ff6b35` → `#ffe6b0` 两层环 | 射线 `#ff6b35` |
| 电弧 | `#7bd6ff` | 折线 + 短促白闪 `#f3ecdd` |
| 蜂群 | `#c9a0ff` | 三颗一组的小方点 |
| 治疗/经验 | `#9ad14f` | 上升的小方块 |

## 3. 特效清单

每种给：触发条件、视觉、持续时间、**同时上限**。上限是必须的——没有上限的特效在 160 敌人同屏时会杀掉帧率。

| id | 触发 | 视觉 | 时长 | 上限 |
|---|---|---|---|---|
| `muzzle` | 玩家开火 | 炮口 3 段短射线 + 1 个亮点 | 0.08s | 12 |
| `trail` | 子弹每帧 | 沿速度方向的分段矩形，透明度递减 | 0.12s | 400 |
| `hit` | 子弹命中 | 命中点 6 条细射线（星形）+ 中心亮点 | 0.14s | 60 |
| `crit` | 暴击 | 同上，射线 ×2 长度，额外一圈小环 | 0.18s | 20 |
| `blast` | 爆炸 | 双层同心环向外扩 + 12 条径向射线 | 0.30s | 24 |
| `chain` | 电弧连锁 | 折线（每段 3 个锯齿点）从源到目标，白闪 2 帧 | 0.16s | 16 |
| `pierce` | 穿透 | 在穿透点留下一条垂直于弹道的短线 | 0.20s | 30 |
| `kill` | 敌人死亡 | 8–22 个方形碎块向外飞散 + 地面留 0.6s 淡痕 | 0.5s | 90 |
| `shield_break` | 护盾破碎 | 六边形网格从击中点向外碎裂 | 0.22s | 2 |
| `shield_hit` | 护盾吸收 | 击中点局部六边形亮起 | 0.12s | 8 |
| `pickup` | 拾取经验 | 小方块向 HUD 方向飞（0.25s 后消失） | 0.25s | 40 |
| `nova` | 壁垒形态冲击波 | 全屏可见的大环，向外扩到 380px | 0.45s | 1 |
| `boss_phase` | BOSS 阶段转换 | 车体边缘亮度脉冲 2 次 | 0.5s | 1 |
| `levelup` | 升级 | 玩家周围上升 12 个方块 + 环 | 0.6s | 1 |
| `low_hp` | 血量 < 30% | 屏幕边缘红色暗角脉动（不是全屏红） | 持续 | 1 |

**屏幕震动**也在总线里，但它走 `ctx.options` 的 `screen-shake`，可以被玩家关掉：

| id | 强度 | 时长 |
|---|---|---|
| `shake_hit` | 3px | 0.08s |
| `shake_blast` | 6px | 0.12s |
| `shake_boss` | 10px | 0.18s |
| `shake_nova` | 14px | 0.22s |

## 4. 实现约束

| 项 | 要求 |
|---|---|
| 内存 | 对象池，预分配 900 个粒子槽位，不 `new`、不 `push` 到无界数组 |
| 排序 | 只按 `layer`（地面 / 实体下 / 实体上 / 覆盖）画，不逐帧排序 |
| 混合模式 | `globalCompositeOperation = 'lighter'` 仅用于能量类特效，画完立刻重置为 `source-over` |
| 禁用模糊 | 不用 `shadowBlur`、不用 `filter`（电视 GPU 上开销大，实测掉帧） |
| 透明 | 用 `globalAlpha` 或 `rgba()`，不要为了半透明改 `fillStyle` 字符串（每帧分配字符串） |
| 关闭 | `screen-shake` 关掉后不改变换矩阵；低血量暗角属于信息反馈，不受影响 |

## 5. 每台坦克的签名特效

签名技能是"高端坦克"的卖点，所以每台必须有一个**一眼能认出是谁**的特效。

| 坦克 | 签名 | 专属特效 |
|---|---|---|
| 铁砧 | 稳定炮座 | 静止 1.5s 后炮塔两侧亮起两条短稳定光带（呼吸） |
| 回声 | 轻量履带 | 冲刺结束后 1s 内，炮口带一圈淡青光环 |
| 港湾 | 应急装甲 | 血量 < 30% 时车体描边变成脉动的琥珀色 |
| 长矛 | 贯穿校射 | 每穿透一个目标，弹道上亮起一颗青点，最多 3 点 |
| 熔炉 | 装药过量 | 爆炸环外再套一圈虚线环（装药过量） |
| 电弧 | 导电链 | 连锁折线末端有一个小电弧球，会跳动 |
| 蜂群 | 蜂群协议 | 命中叠层时，目标身上出现 1–5 个小十字标记 |
| 终焉 | 要塞协议 | 每 12s 齐射前 0.5s，车体四周亮起 8 个蓄能点 |

**这些特效不复用**。它们存在的意义就是"我换了坦克，我能看出来"。

## 6. 性能预算

| 类别 | 上限 | 单帧绘制调用估算 |
|---|---|---|
| 粒子 | 900 | 900 次 `fillRect`（方形碎块，比 `arc` 快） |
| 拖尾 | 400 | 400 次 `fillRect` |
| 环 / 射线 | 120 | 120 次 `arc` + 少量 `lineTo` |
| 折线 | 32 | 32 次 `stroke` |

按 960×540 的矢量化绘制，单帧绘制总量应在 **8ms 以内**。超过就按"先砍 `trail`，再砍 `kill`"的顺序降级——拖尾最容易砍且最不影响可读性。

## 7. 可访问性

| 项 | 做法 |
|---|---|
| 震动 | 设置项 `screen-shake`：强 / 弱 / 关 |
| 闪烁 | 所有闪烁频率 ≤ 3Hz（避免光敏性癫痫） |
| 颜色 | 不靠颜色单独传递信息：暴击有更大射线、精英有紫边 + 更大体型 |
| 低视力 | HUD 数字 18px 起，主要信息带图形（血条、进度环） |
